# Student IMU measurements (ME 3310)

This folder provides a local MAT-file inspection and standardization layer for student measurements; it is NOT a new classifier. It was developed against two sample files named trial_T01.mat and trial_T02.mat (not committed to GitHub).

## Week 11 / Canvas Page 01: real USC-HAD measurement demonstrations

**Whole trial versus the first measured sliding window (Page 01, Section 3):**
The `"time"` mode computes Mean, sample STD, RMS, peak and jerk using
**every sample in a single original trial**. It does not compute the
first 3-s analysis window. The new `"timecompare"` mode makes a
direct, apples-to-apples comparison of the **whole original trial**
against the **first 3 seconds (300 samples at USC-HAD's 100 Hz)**
and displays a comparison table and a figure.

```matlab
repo = gitrepo; pull(repo);  % from your existing repository root
addpath(fullfile(pwd,"examples","Student_IMU"));
R = week11_01_feature_demo("time","upstairs");
disp(R.timeFeatures)               % WHOLE original trial
C = week11_01_feature_demo("timecompare","upstairs");
disp(C.timeComparison)              % WHOLE versus FIRST 3-s window
D = week11_01_feature_demo("timecompare","downstairs");
disp(D.timeComparison)
```

This demonstration analyzes only measured USC-HAD samples, without
generating data. Both summaries refer to the SAME original trial
and therefore are not independent experimental repetitions. Run
`week11_01_feature_demo("windows","upstairs")` to examine multiple
overlapping 3-s windows with 0.5-s hop. No classifier or feature
selection is performed by the comparison command.

### Week 11 Canvas Page 05 — Uncertainty and Reliability of Classification

Run [week11_05_uncertainty_demo.m](week11_05_uncertainty_demo.m) using the
real USC-HAD five-motion feature and SVM summary files produced by
step07–step09. From the repository root:

```matlab
repo = gitrepo;
pull(repo);
addpath(fullfile(pwd,"examples","Student_IMU"));
U = week11_05_uncertainty_demo("all");
disp(U.featureIntervals)
disp(U.subjectReport)
disp(U.classRecall)
```

The script shows: (1) five independent Upstairs / Downstairs trials
for Subject 2, with descriptive mean and 95% Student-t confidence
interval for two trial-mean features, (2) cross-validation balanced
accuracy by held-out subject for the original 8 vs expanded 16 features,
and (3) five-class original-trial confusion and class-specific recall.
Options: `"features"`, `"subjects"`, `"errors"`, or `"all"`.

**Do not equate different uncertainty quantities.** The displayed
t confidence interval applies to a class mean of measured features
under approximately independent and normal original-trial summaries.
Overlapping windows are not independent trials. The plotted differences
between held-out subjects are NOT a classical confidence interval on
model generalization because leave-one-subject-out training folds
overlap. These actual USC-HAD recordings do not measure genuine
motion-transition latency or service reliability for new PocketLab
users. MATLAB runtime testing has not been independently completed.

### Week 11 Canvas Page 04 — Two motions to five, 8 vs. 16 features

Page 04 is a **separate Canvas lesson**. The established five-class
linear SVM experiment already exists in the USC-HAD directory.
Use the ORIGINAL measured USC-HAD activities (Walking Forward, Upstairs,
Downstairs, Running Forward, Standing). Each trial has ONE true class:
this is multiclass classification, not multilabel classification.

From the root of the already-cloned repository:

```matlab
repo = gitrepo;
pull(repo);
run("examples/USC_HAD/step07_prepare_five_motions.m");
run("examples/USC_HAD/step08_extract_five_motion_features.m");
run("examples/USC_HAD/step09_train_five_motion_svm.m");
```

These existing scripts compute 16 physical IMU features, then compare
**8 original features** with all **16** using a one-versus-one linear
ECOC SVM. They produce development-subject cross-validation scores and
a five-class original-trial confusion matrix. The classifier trains
on overlapping windows and uses **majority vote over each original
single-activity trial** to form a trial prediction. Page 03's
two-motion example instead trains on averaged trial feature vectors;
its scores are NOT directly comparable to this different pipeline.

Measured data are at 100 Hz; the high-frequency bands cannot be
transferred to the students' planned 20-Hz recordings without changes.
Previously viewed diagnostic subjects are not a fresh independent test.
No additional classifier or generated signal is needed for Page 04.
Next, Page 05 addresses measurement uncertainty and reliability.

### Week 11 Canvas Page 03 — Real-trial Logistic Regression and Linear SVM

The lesson companion [week11_03_classifiers_demo.m](week11_03_classifiers_demo.m) reads the measured USC-HAD 16-feature file generated by `step03_extract_window_features.m`. It averages overlapping window features **inside each original trial** before training binary logistic regression and a linear support vector machine. This avoids treating multiple overlapping windows as independent experimental repetitions. One row represents a completed Upstairs or Downstairs trial, not continuous transition detection.

```matlab
% From repository root, after step01 and step03:
addpath(fullfile(pwd,"examples","Student_IMU"));
M = week11_03_classifiers_demo("manual",[1 2]);
disp(M.trainingReport);
disp(M.diagnosticReport);
M.confusionLogistic
M.confusionSVM

% Optional feature-screening experiment, limited to development subjects:
M = week11_03_classifiers_demo("search");
disp(M.candidateResults);
disp(M.featurePair);
```

This exercise separates 10 development subjects from 4 diagnostic subjects (previously examined, NOT a pristine final test). It compares model decisions and original-trial confusion matrices, and optionally uses leave-one-subject-out logistic CV over six candidate pairs for screening; it does not automatically optimize all feature combinations or model hyperparameters. Standardization is trained only on development or cross-validation training folds. Requires Statistics and Machine Learning Toolbox (`fitglm`, `fitcsvm`). MATLAB runtime verification is pending.


[week11_02_fisher_lda_demo.m](week11_02_fisher_lda_demo.m) uses the actual USC-HAD trial-summary output returned by [week11_02_feature_compare_demo.m](week11_02_feature_compare_demo.m). Run:

```matlab
C = week11_02_feature_compare_demo(2,[1 2]);
D = week11_02_fisher_lda_demo(C,[1 2]);
disp(D.fisherTable);
D = week11_02_fisher_lda_demo(C,[1 3]);
```

The script compares observed class means and sample STD for all 16 features, plots one-dimensional Fisher Scores, prints correlations for the chosen pair within each class, and displays an LDA direction and projected trial points. Each data point comes from an original trial (mean of its overlapping window features); LDA uses standardized features and a small explicit numerical regularizer. This is **in-sample feature exploration**, not held-out classification performance. Repeated trials of the same person cannot establish performance on new subjects. The calculations do not automatically select the best pair; students should use physical reasoning, observations, and repeatability. No new data are fabricated. MATLAB execution has not been independently verified.

The new script [week11_02_feature_compare_demo.m](week11_02_feature_compare_demo.m) generates three figures: one-dimensional feature distributions for each original trial (with mean ± sample STD), a 2D feature scatter, and class-mean acceleration-magnitude PSD computed from **real** USC-HAD measurements. Default Subject 2 has five original upstairs trials and five original downstairs trials; windows are averaged within original trials before plotting. Feature indices [1 2] represent acceleration magnitude STD vs 0.8-3 Hz PSD band power, consistent with the project's pre-existing 16-feature matrix. Try "all" as the first argument to examine subject-to-subject variability, and select different feature indices to test your own hypothesis. No automatic feature selection or classifier training takes place. MATLAB verification is still pending.

For an existing checkout, run `repo = gitrepo; pull(repo);` from its root, and prepare data only if the `ME3310_USC_HAD_UpDown.mat` file is missing. The dataset is downloaded from [USC-SIPI](https://sipi.usc.edu/had/), not included in this repository.

For your own measurement, point the same function to an actual student MAT file:

```matlab

```

Absent sensor channels are left empty; their values are never fabricated. Source sampling rate matters: USC-HAD is **100 Hz (Nyquist 50 Hz)**, while the planned student IMU setting is **20 Hz (Nyquist 10 Hz)**. The demonstration examines 0.5–3 and 3–8 Hz bands; the band boundaries are exploratory choices rather than optimized features. Welch PSD requires Signal Processing Toolbox. These scripts support observation and interpretation, not an automatic classification result.


## Run

From the repository root, use MATLAB:

    repo = gitrepo;
    pull(repo);
    run("examples/Student_IMU/step01_inspect_student_mat.m")

Select one or more local MAT files in the dialog. The script checks timestamps, sampling frequency, number of samples, available sensor channels and optional event labels. It plots acceleration and/or gyro signals, including acceleration-magnitude PSD when Signal Processing Toolbox is available.

The reusable loader load_student_trial.m returns:
- trial.t: time in seconds, starting at zero
- trial.fs: rate estimated from timestamps
- trial.acc: Nx3 acceleration when present, otherwise empty
- trial.gyro: Nx3 angular velocity when present, otherwise empty
- trial.label: optional meta.EventLabel; never inferred from filename
- trial.meta: original measurement metadata
- trial.units: optional declared physical units (not automatically converted)

## Two actual student example recordings

- T01: 104 samples at 20 Hz, t=0..5.15 s
- T02: 100 samples at 20 Hz, t=0..4.95 s
- Both contain Nx3 accel, Nx1 t, meta, but NO gyro
- Measured magnitudes near one raw unit suggest but do not independently prove accelerometer unit g. Verify meta.Units.accel in MATLAB.

For 20 Hz acquisition, Nyquist is 10 Hz. The previous USC-HAD 8-12 Hz, 12-20 Hz and 20-40 Hz bands cannot be reused. A 2-second Welch segment also provides only about 0.5 Hz native resolution. Because no gyro was measured, never replace absent angular-rate channels with fabricated zeros.

T02 includes a magnitude peak of approximately 7.94 raw acceleration units at 3.10 s, largely from a Y-axis excursion. Verify whether this is real impact or an artifact. Both sample files report one invalid driver packet; the logs do not prove that the peak was caused by it.

## Before classification

Collect multiple independent, labeled trials per motion, confirm acceleration units, placement/orientation and sampling, select appropriate accel-only features, and split by trial or by subject before evaluation. Overlapping windows are NOT independent experimental replicates.

## Privacy

Do NOT add student raw data, Bluetooth addresses, raw sensor packets or other identifying device metadata to this repository. The local MAT/CSV files are gitignored in this folder. Only code is committed.

The MATLAB scripts have been reviewed structurally but not executed in a MATLAB installation.
